# Fire-Operator: Двухэтапный космический мониторинг природных пожаров и оценка гарей

Программно-аппаратный комплекс двухэтапного мониторинга природных пожаров по данным ДЗЗ в рамках соревнований **«КосмоХакатон 2026»**.

Решение включает в себя:
1. **Модуль 1 (Active Fire / AF):** Высокоточный физико-статистический детектор пикселей активного горения по данным каналов VIIRS I1–I5 (375 м/пикс) с фильтрацией техногенных факелов и солнечных бликов.
2. **Модуль 2 (Burn Severity / BS):** Многоканальный классификатор контуров гарей и разделения трёх степеней поражения (1 — слабая, 2 — средняя, 3 — сильная) по многоспектральным парам «до/после» Sentinel-2 L2A (20 м/пикс), радиолокационным данным Sentinel-1 SAR (VV/VH) и рельефу.
3. **CLI Инференса (`inference.py`):** Автономный скрипт формирования `submission.csv` с гарантированной скоростью работы **менее 30 секунд** на полный тестовый набор.
4. **Информационно-аналитический сервис (`backend`):** Полнофункциональный REST API на FastAPI с пространственно-временным анализом, геодезическим расчётом площадей в гектарах (зоны UTM 37N / 38N) и экспортом векторных контуров в **GeoJSON** и **Shapefile ZIP**.

## 1. Архитектурная схема комплекса

```
                          ┌──────────────────────────┐
                          │   ВХОДНЫЕ ДАННЫЕ (ЧИПЫ)  │
                          └─────────────┬────────────┘
                                        │
             ┌──────────────────────────┴──────────────────────────┐
             ▼                                                     ▼
   [МОДУЛЬ 1: AF-ЧИПЫ (375м)]                            [МОДУЛЬ 2: BS-ЧИПЫ (20м)]
   • VIIRS I1-I5 + AUX (WorldCover, DEM, ERA5)           • Sentinel-2 (Pre/Post) + Sentinel-1 SAR
             │                                                     │
  [Физико-контекстный пайплайн]                         [Спектрально-радарный пайплайн]
   • Радиационный контраст (I4 - I5)                     • Индексы: dNBR, RdNBR, dNDVI, dSWIR
   • Скользящий фон (21x21 Z-score)                      • Дельта красного dRed (гарь vs солома)

      [ML-Классификатор]                                    [ML-Классификатор]

             │                                                     │
             ▼                                                     ▼
     Бинарная маска AF (0, 1)                              Маска классов BS (0, 1, 2, 3)
             │                                                     │
             └──────────────────────────┬──────────────────────────┘
                                        ▼
                           ┌─────────────────────────┐
                           │      inference.py       │  -> submission.csv (< 30 сек!)
                           └────────────┬────────────┘
                                        │
                                        ▼
             ┌─────────────────────────────────────────────────────┐
             │       ИНФОРМАЦИОННО-АНАЛИТИЧЕСКИЙ ГЕОСЕРВИС         │
             │                   (FastAPI REST)                    │
             │  • POST /api/v1/analyze (BBox / Полигон + даты)     │
             │  • GET  /api/v1/report/{id} (Площади в га и %)      │
             │  • GET  /api/v1/export/geojson/{id}                 │
             │  • GET  /api/v1/export/shapefile/{id} (ZIP: shp,dbf)│
             └─────────────────────────────────────────────────────┘
```

## 2. Системные требования и установка

* **Python:** 3.10 / 3.11 / 3.12 / 3.14
* **ОС:** Linux (Ubuntu 22.04+), Windows 10/11, macOS
* **Аппаратные требования:** CPU (от 4 ядер) или GPU с поддержкой CUDA. Объем RAM от 8 ГБ.

### Установка зависимостей:
```bash
pip install -r requirements.txt
```

---

## 3. Запуск инференса (Проверка организаторами)

Запуск инференса выполняется строго единой командой из корня репозитория:
```bash
python inference.py --data-dir /path/to/test --output /path/to/submission.csv
```

### Гарантии инференса:
* **Время работы:** $< 30$ секунд на полный тестовый набор (максимальные 8 баллов);
* **Формат:** Ровно 447 строк, 1-based RLE-кодирование со строками в двойных кавычках (`"start len"`);
* **Корректность:** Полное совпадение набора пар `(chip_id, class_id)`, отсутствие `NaN` и пропусков, взаимоисключение масок классов 1, 2, 3 внутри одного чипа.

## 4. Обучение моделей

Все обученные веса уже сериализованы и лежат в папке `weights/` (`af_model.joblib`, `bs_model.joblib`).

Для повторного воспроизводимого запуска обучения выполните:
```bash
python ml/train.py
```
Скрипт автоматически проведет обучение на чипах обучающей выборки, выведет метрики валидации ($F_{1\_af}$, $\text{IoU}_{burn}$, $\text{mIoU}_{sev}$, Score) и перезапишет файлы весов.

## 5. Информационно-аналитический геосервис (FastAPI)

### Запуск сервиса:
Из каталога `backend/`:
```bash
cd backend
uvicorn app.main:app --host 0.0.0.0 --port 8000
```
Интерактивная документация Swagger UI доступна по адресу: `http://localhost:8000/docs`.

### Основные эндпоинты REST API:

| Метод | Эндпоинт | Описание |
|---|---|---|
| `POST` | `/api/v1/analyze` | Постановка пространственно-временного запроса по BBox/полигону и датам |
| `GET` | `/api/v1/tasks/{task_id}` | Опрос статуса и прогресса выполнения задачи |
| `GET` | `/api/v1/report/{task_id}` | Получение официальной аналитической справки (площадь в га, доли степеней) |
| `GET` | `/api/v1/export/geojson/{task_id}` | Выгрузка векторных контуров в формате **GeoJSON** (RFC 7946, WGS84) |
| `GET` | `/api/v1/export/shapefile/{task_id}` | Выгрузка векторных контуров в **ESRI Shapefile ZIP** (shp, shx, dbf, prj, cpg) |
| `GET` | `/api/v1/health` | Проверка статуса сервиса, доступности моделей и диска |

### Пример cURL-запроса на анализ территории:
```bash
curl -X POST "http://localhost:8000/api/v1/analyze" \
     -H "Content-Type: application/json" \
     -d '{
       "bbox": [43.0, 47.0, 45.5, 48.5],
       "date_from": "2024-05-01",
       "date_to": "2024-09-30",
       "include_radar": true
     }'
```

## 6. Запуск в Docker

Для изолированного развёртывания контейнера:
```bash
# Сборка образа
docker build -t fire-operator:latest .

# Запуск REST API сервиса
docker run -d -p 8000:8000 --name fire-operator fire-operator:latest

# Запуск тестового инференса через Docker
docker run --rm -v /path/to/test:/data fire-operator:latest \
    python inference.py --data-dir /data --output /data/submission.csv
```
